# Huawei notifications for T3 Code

The Go desktop companion pairs with the official macOS or Windows T3 Code installation as a read-only client. It sends task status to a Go service on your server. The HarmonyOS app registers with that service after the user authorizes with the Huawei account on the phone. Only devices registered to the same verified Huawei account, T3 environment, and notification type receive the event. T3 Connect handles the remote environment connection.

## Server

Build the service with Go 1.25 or later from this directory.

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o huawei-push .
```

Use `GOARCH=arm64` for an ARM server. Run `./huawei-push serve` as a dedicated service user and configure its environment outside the repository.

| Variable                                                             | Value                                                                                                                                                                         |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HUAWEI_PUSH_DESKTOP_CLIENT_ID`, `HUAWEI_PUSH_DESKTOP_CLIENT_SECRET` | Account Kit OAuth credentials for desktop device-code authorization.                                                                                                          |
| `HUAWEI_PUSH_MOBILE_CLIENT_ID`, `HUAWEI_PUSH_MOBILE_CLIENT_SECRET`   | Account Kit OAuth credentials for the signed HarmonyOS app. Both OAuth clients must belong to the same Huawei developer account so they return the same UnionID for one user. |
| `HUAWEI_PUSH_SERVICE_ACCOUNT_FILE`                                   | Path to the private Push Kit service-account JSON from AppGallery Connect.                                                                                                    |
| `HUAWEI_PUSH_PROJECT_ID`                                             | Push Kit project ID when the key file does not include it.                                                                                                                    |
| `HUAWEI_PUSH_STATE_FILE`                                             | Writable path for the session and delivery state, such as `/var/lib/t3-huawei-push/state.json`. Use one service process per file.                                             |
| `HUAWEI_PUSH_LISTEN_ADDR`                                            | Listener, default `127.0.0.1:8080`.                                                                                                                                           |
| `HUAWEI_PUSH_TLS_CERT_FILE`, `HUAWEI_PUSH_TLS_KEY_FILE`              | Certificate chain and private key when terminating TLS in the Go service.                                                                                                     |

For an existing reverse proxy, leave the service on loopback and route a dedicated HTTPS origin to it. Direct public listeners require both TLS settings. Use `GET /healthz` to check service availability. Restrict the state and credential files to the service user. Enable the `WORK` notification category in Push Kit. [Huawei Push Kit authorization](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/push-jwt-token/) · [Huawei Code authorization](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/account-authorize-by-qrcode/) · [Huawei account identifiers](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/account-kit-faq-0001/)

The service persists accepted notification events before acknowledging them. It retries temporary delivery failures for up to ten minutes and deduplicates events for 24 hours. Requests carry the environment ID, thread ID and event phase. Notification text is generated by the service.

## Mac and Windows

Build the companion with your HTTPS origin so users can open it directly.

```sh
origin=https://push.example.com
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath \
  -ldflags="-X main.defaultPushURL=$origin" -o t3-huawei-push ./desktop
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath \
  -ldflags="-H windowsgui -X main.defaultPushURL=$origin" -o t3-huawei-push.exe ./desktop
```

Open the companion, connect to the running local T3 Code, and scan the Huawei authorization QR code. The companion uses the official `t3 pair` command with `orchestration:read`. After setup it installs itself for the current OS user and starts at sign-in. Open the companion again to reconnect T3 Code or sign out of Huawei. Both sessions can expire and be reauthorized in that screen. For local testing, pass `-server` with a loopback HTTP origin.

The watcher subscribes to active thread state. It does not emit a notification for the initial snapshot. In-process reconnects can recover recent events that are available in T3 Code's stream. The watcher covers top-level threads and ignores stopped, snoozed and background-progress completion events.

## HarmonyOS

Configure the HTTPS origin and HarmonyOS OAuth client ID when building the shared mobile app. Pair the phone to the same T3 environment, then enable **Background notifications** after authorizing under **Settings → Huawei Account**.
